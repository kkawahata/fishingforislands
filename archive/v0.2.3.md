# v0.2.3 — Progress bars for farming actions
Date: 2026-04-22

## Summary
Farming-style actions (fishing, picking up resources, drawing water,
crafting, etc.) previously resolved instantly. They now run through a
shared action-bar primitive that shows a floating progress bar anchored
above the target for 0.8–2.5 seconds. Waiting is gameplay — the bars
give actions visible weight and let the player feel the tick of each
"job."

## Architecture

### Shared UI primitive
`UI.showActionBar(label)` / `updateActionBar(progress, screenX, screenY)` /
`hideActionBar()`. One DOM element (`#action-bar`) reused across every
action type, positioned each frame in screen space from a projected
world target.

### Game loop
New `action` mode. `Game._startAction({ targetMesh, duration, label,
onComplete })` locks player input and stores the pending action. The
update loop's `action` branch advances elapsed time, projects the
target to screen, and updates the bar. When `elapsed >= duration`,
`_finishAction` clears state, restores `mode = 'playing'`, re-enables
input, and fires `onComplete` — which performs the actual game-state
mutation (add item, consume inputs, etc.).

Order matters: `_finishAction` resets mode to `'playing'` *before*
calling `onComplete`, so callbacks are free to set `mode = 'dialogue'`
(fire lighting) or reopen the crafting menu without getting clobbered.

## Durations
- Pickup (driftwood, seaweed, axe, etc.) — **0.8s**
- Well (drawing water) — **1.5s**
- Sheep shearing — **1.5s**
- Crafting (any recipe) — **1.5s**
- Wheat field (dig / plant / harvest) — **2.0s**
- Fishing (pier) — **2.5s**
- Fire pit (lighting) — **2.5s**

## Handlers refactored
- `_handlePickup` — target = pickup mesh
- `_handleWell(mesh)` — target = well
- `_handlePier(mesh)` — target = pier; early-out when daily cap reached
  so the bar doesn't show for a no-op
- `_handleWheatField(mesh)` — three branches (dig/plant/harvest), each
  with its own bar
- `_handleSheepInteraction` — the normal shear branch
- `_handleFirePit(mesh)` — only the lighting branch; cooking keeps its
  existing dialogue pacing
- `_handleCraftStation(mesh, data)` — threaded the station mesh through;
  on recipe click the menu closes, the bar floats above the station,
  and the menu reopens on complete so the player can chain crafts

## Not changed
- Mining (`_handleMiner`) and mountain climbing (`_handleMountain`)
  already use dialogue sequences that pace them; leaving those alone.
- Tree chopping — no tree objects exist in the world yet (logs have no
  in-game source). Would be a separate feature to add.

## Files
- `index.html` — action-bar element + CSS.
- `src/UI.js` — bar show/update/hide methods.
- `src/Game.js` — `_startAction`/`_updateAction`/`_finishAction`,
  `action` mode wired into update loop, handler refactors, `mesh`
  threaded through crafting station dispatch.
- `package.json`, `src/version.js` — bumped to `0.2.3`.
