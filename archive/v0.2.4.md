# v0.2.4 — Quest editor (dev tool) + extended quest schema
Date: 2026-04-22

## Summary
New standalone admin page at `/admin.html` for viewing, searching,
editing, and exporting quest definitions. Vite now builds it as a
second entry point alongside the game, and a "Quest Editor ↗" link
lives in the in-game dev tools panel.

The quest schema is extended with new optional fields — `islands[]`
(multi-island gating), `requiresQuests[]` (prerequisite quests),
`rewards` (object map of resource → count), and `dialogue` (refs to
entries in `DIALOGUES`). `GameState.getActiveQuests` now reads both
the legacy single `island` and the new `islands[]` (AND semantics
across all listed islands), and gates by `requiresQuests` where set.
Every existing quest continues to work without edits.

## What the editor does
- **View**: list all quests in the left sidebar, full detail view on
  the right.
- **Search**: filters by id, name, description, island ids, and step
  text / step ids.
- **Edit**: metadata, islands, requires, rewards, dialogue refs, and
  per-step id/text/check-source.
- **Add/remove steps**: with reorder buttons.
- **Create/delete quests**: via toolbar buttons.
- **Export**: download as `.js` (drop-in replacement for the QUESTS
  export in `data.js`), `.json` (for tooling), or "Copy JS" to
  clipboard.

## `check` functions — how they round-trip
Step `check` functions aren't JSON-serializable, so the editor stores
each check as **source text** (captured via `Function.prototype.toString`
on load). That text is editable in a textarea per step, and re-emitted
as JS in the export. JSON export keeps the source text as a string in
the `check` field — not executable, but useful for tooling / diffing.

## Closing the loop from editor → game (answer to "what else would we need?")
The game is a purely static site, so the browser can't write files
directly. Options, ordered by cost and tradeoffs:

1. **Copy-paste / download** (what we ship today). Export .js,
   manually paste into `src/data.js`. Zero infra; manual round-trip.
2. **localStorage overlay for live preview**. Editor saves JSON to
   `localStorage.questsOverride`; game deep-merges that over `QUESTS`
   at init. Lets playtesters see edits in the same browser without a
   build step. Doesn't persist to git.
3. **Move QUESTS into a standalone .json**, loaded by `data.js` at
   runtime. Editor fetches + re-serializes. Combined with a tiny local
   `npm run admin-server` (dev-only Node) that accepts `PUT /quests.json`
   and writes to disk, this is a one-click save. Requires that `check`
   functions become structured predicates (e.g. `{ type: 'flag',
   flag: 'picked_axe' }`) since JSON can't hold functions.
4. **File System Access API** (Chrome/Edge only). Editor prompts the
   dev once per session to pick `src/data.js` and writes directly. No
   server; no Firefox.
5. **GitHub API commit**. Editor commits via the GitHub REST API using
   a personal access token, pushing directly to `main`. Closes the
   loop all the way to the deployed site. Requires token handling.

Recommended next step for this project: add (2) so edits in the admin
tool show up live in the game for the same browser session, then
consider (3) + structured predicates if we outgrow the copy-paste flow.
