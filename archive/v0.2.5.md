# v0.2.5 — localStorage override for live quest editing + refactor proposal
Date: 2026-04-22

## Summary
Closes the editor→game loop (option 2 from the v0.2.4 proposal). The
Quest Editor now has an **Apply to Game** button that saves the
current quest model to `localStorage`; `data.js` merges the override
into `QUESTS` at module load, so a reload of the game tab picks up
edits with no rebuild or file write. A yellow chip on the game page
("🧪 quest override active") appears whenever an override is live and
clears it on click.

Also lands a written refactor proposal (`docs/quest-refactor-proposal.md`)
answering the question "each quest should contain all of its
associated information." Inventory + three scoped options; the
recommendation is Option B (move quest-specific dialogue and rewards
onto the quest, add a per-quest state bucket for counter flags, keep
shared-world flags as-is).

## Architecture

### `src/questsOverride.js`
Small module with four responsibilities:
- `hasOverride()` / `loadOverride()` / `saveOverride(obj)` /
  `clearOverride()` — localStorage I/O.
- `applyOverrideInPlace(quests)` — called once from `data.js`; if an
  override exists, wipes every key on the live `QUESTS` object and
  repopulates from the override. Mutating in place keeps the
  `export const QUESTS = {...}` binding and every downstream import
  stable.
- Handles the check-function problem: the editor stores
  `step.check` as source text (via `Function.prototype.toString`).
  When reconstituting, strings are compiled back with
  `new Function('return (' + src + ');')()`. Malformed sources fall
  back to `() => false` with a console warning, so the game never
  crashes on a broken predicate.

### Storage shape
```json
{
  "schemaVersion": 1,
  "savedAt": "2026-04-22T…",
  "quests": { "home_q1": { … }, "…": { … } }
}
```
Full replacement — if the override exists, the game sees exactly the
quests in it (nothing from the code-defined base). `schemaVersion`
gives us an upgrade hook later.

### Editor additions
- **Apply to Game** (primary button) — saves the full model to
  localStorage, clears dirty flags, refreshes the status indicator.
- **Clear Override** — removes the localStorage entry (after
  confirm), leaves the editor's in-memory edits intact.
- **Status strip** shows `● override active` / `○ no override` next
  to the button cluster.

### Game indicator
- `#quest-override-chip` sits under the version chip in the
  top-left, hidden by default. `main.js` checks `hasOverride()` at
  startup; when true the chip is visible and clickable — clicking
  clears the override and reloads.

## Proposal (in `docs/quest-refactor-proposal.md`)

**Inventory** — what is not on the quest today:
1. ~22 of ~29 `DIALOGUES` entries are 1:1 quest-owned.
2. Rewards (stones, coins, items) are awarded inline inside handlers.
3. ~60 `gameState.flags` — many are pure quest bookkeeping.
4. Handler functions mix first-meeting dialogue, quest logic, and
   rewards.
5. No explicit NPC→quest binding; implicit via handler branches.
6. `ISLAND_UNLOCK_RULES` and `quest.requiresDay` overlap without a
   structural link.
7. Winter and pregnancy state machines live outside their driving
   quests (`forest_q3`, `sheep_q3`).
8. Meta-quests (`mystery_q2`, `rocks_q3`) don't expose their chain
   relationships.

**Recommendation — Option B** (see doc for A and C):
- Move quest-specific `DIALOGUES` entries onto the quest as
  `dialogue: { onStart, onComplete }`. Keep `DIALOGUES` for truly
  shared lines (turtle daily, generic NPC chatter).
- Add `rewards: { item: count }` with a generic
  `_applyQuestCompletion` helper that awards them.
- Introduce `gameState.questState[id] = {}` and migrate counter
  flags (`mouse_catches`, `theodore_day`, etc.) into it.
- Add declarative `onComplete: { unlockIsland?, giveItems?,
  setFlags? }`; handler code for those effects disappears.

Suggested phasing: v0.3.0 (dialogue + rewards migration — minor
bump, it's structural), v0.3.1 (per-quest state bucket),
v0.3.2 (declarative onComplete effects), v0.4.0 optional declarative
step predicates toward Option C.
